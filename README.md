# ProjectTelBotMark

Telegram-бот для приёма заказов на товары с веб-интерфейсом администратора. Проект написан на Go, использует SQLite для хранения данных, Telegram Bot API для общения с покупателями и Gin для административной панели.

## Возможности

### Telegram-бот

- Просмотр каталога товаров по категориям и подкатегориям.
- Добавление товаров в корзину и изменение количества кнопками «+» и «−».
- Просмотр корзины и автоматический пересчёт общей стоимости.
- Избранные товары.
- Просмотр предыдущих заказов и повтор последнего заказа.
- Оформление заказа с указанием даты доставки, телефона, ФИО и адреса.
- Подтверждение выбранной даты доставки и возможность изменить её.
- Комментарий к заказу.
- Выбор способа оплаты: наличные или перевод на карту.
- Сохранение данных покупателя для повторного оформления заказа.
- Рассылка информационных сообщений пользователям.
- Ежедневная фоновая проверка напоминаний.

### Веб-интерфейс администратора

- Просмотр и управление каталогом товаров.
- Добавление, редактирование и удаление товаров.
- Загрузка изображений товаров.
- Фильтрация, сортировка и постраничный просмотр каталога.
- Экспорт товаров в Excel.
- Просмотр информации и статистики по заказам.
- Управление чёрным списком пользователей.
- Рассылка информационных сообщений покупателям.

## Технологии

- **Go 1.26.0**
- **Telegram Bot API** — `github.com/go-telegram-bot-api/telegram-bot-api/v5`
- **Gin** — веб-сервер и административная панель.
- **SQLite** — база данных (`github.com/mattn/go-sqlite3`).
- **Viper** — чтение конфигурации.
- **Excelize** — экспорт данных в Excel.
- **slog-avp/v2** — логирование.

## Установка и запуск

### 1. Клонирование проекта

```bash
git clone https://github.com/Anatoly8853/ProjectTelBotMark.git
cd ProjectTelBotMark
```

### 2. Подготовка конфигурации

Скопируйте пример конфигурации:

**Windows PowerShell:**

```powershell
Copy-Item app.env.example app.env
```

**Linux:**

```bash
cp app.env.example app.env
```

Откройте `app.env` и заполните параметры:

```dotenv
TELEGRAM_TOKEN=токен_telegram_бота
TELEGRAM_GROUPCHATID=
TELEGRAM_CHATID=
DB_NAME=./sqlite/data.db

ADMIN_USERNAME=admin
ADMIN_PASSWORD=укажите_надёжный_пароль_не_короче_12_символов

WEB_ADDR=127.0.0.1:8090
TLS_CERT_FILE=
TLS_KEY_FILE=
```

Назначение параметров:

| Параметр | Назначение |
|---|---|
| `TELEGRAM_TOKEN` | Токен Telegram-бота |
| `TELEGRAM_GROUPCHATID` | Идентификатор группового чата |
| `TELEGRAM_CHATID` | Идентификатор чата |
| `DB_NAME` | Путь к базе данных в примере конфигурации |
| `ADMIN_USERNAME` | Имя пользователя веб-панели |
| `ADMIN_PASSWORD` | Пароль веб-панели, не менее 12 символов |
| `WEB_ADDR` | Адрес и порт веб-сервера |
| `TLS_CERT_FILE` | Путь к TLS-сертификату |
| `TLS_KEY_FILE` | Путь к приватному TLS-ключу |

**Важно:** в текущей реализации инициализатор SQLite открывает базу по фиксированному пути `./sqlite/data.db`. Параметр `DB_NAME` присутствует в примере конфигурации, но пока не управляет этим путём. Перед первым запуском убедитесь, что каталог `sqlite` существует.

Для локального запуска веб-панели используется адрес `127.0.0.1:8090`. Если задаёте HTTPS, необходимо указать одновременно `TLS_CERT_FILE` и `TLS_KEY_FILE`.

### 3. Установка зависимостей

```bash
go mod download
```

### 4. Запуск

Из корня проекта:

```bash
go run ./cmd
```

Для сборки исполняемого файла:

```bash
go build -o ProjectTelBotMark ./cmd
```

В Windows PowerShell можно собрать приложение так:

```powershell
go build -o ProjectTelBotMark.exe ./cmd
```

Запускайте приложение из корневого каталога проекта: конфигурация и пути к файлам заданы относительно текущего рабочего каталога.

## Веб-панель

После запуска откройте в браузере:

```text
http://127.0.0.1:8090
```

Вход защищён HTTP Basic Authentication. Имя пользователя и пароль задаются через `ADMIN_USERNAME` и `ADMIN_PASSWORD`.

Основные разделы и маршруты:

| Адрес | Назначение |
|---|---|
| `/` | Главная страница |
| `/product` | Каталог товаров |
| `/product/add` | Добавление товара |
| `/info` | Информационная рассылка |
| `/highcharts` | График заказов |
| `/black` | Чёрный список пользователей |

Для работы с веб-панелью приложение должно иметь доступ к каталогу шаблонов и статических файлов внутри `internal/routers/html`.

## База данных и резервное копирование

Приложение использует SQLite. При инициализации создаются необходимые таблицы для пользователей, контактных данных и заказов. База по умолчанию располагается в:

```text
sqlite/data.db
```

В проекте также запускается фоновая процедура резервного копирования базы данных. Не удаляйте каталог `sqlite` и регулярно сохраняйте резервные копии отдельно от рабочей машины.

## Проверки кода

В проект добавлен GitHub Actions workflow. При отправке изменений в `master` и при создании Pull Request в `master` выполняются:

```bash
gofmt -l $(git ls-files '*.go')
go test ./...
go vet ./...
```

Локально можно выполнить:

```bash
go test ./...
go vet ./...
```

Чтобы проверить форматирование всех отслеживаемых Go-файлов:

```bash
gofmt -l $(git ls-files '*.go')
```

Если команда выводит имена файлов, их нужно отформатировать с помощью `gofmt -w путь/к/файлу.go`.

## Безопасность

- Не добавляйте `app.env` в Git: файл содержит токен бота и пароль администратора.
- Используйте длинный уникальный пароль веб-панели (не менее 12 символов).
- По умолчанию веб-сервер слушает только локальный адрес `127.0.0.1:8090`.
- Не публикуйте веб-панель в интернет без HTTPS и дополнительной настройки сетевой защиты.
- Не передавайте токен Telegram-бота и резервные копии базы данных посторонним.
